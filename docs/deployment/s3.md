# Amazon S3 Storage

A block device with `bdev_type: s3` stores its data in an Amazon S3 bucket
(or any S3-compatible store, such as MinIO). Each block becomes one object
named `[prefix/]block_<offset>`. The device can be a standalone `clio_bdev`
pool or a storage tier of `clio_cte_core`.

This page walks through a complete first test: install the pip package, sign
in to AWS with the AWS CLI, create a bucket, point a CTE tier at it, and
confirm that blobs land in S3.

## What you need

| Feature | pip wheel (`iowarp-core` 2.5.1+) | Source build |
|---------|----------------------------------|--------------|
| S3 block device (`bdev_type: s3`) | Included | `-DCLIO_ENABLE_AMAZON_DRIVE=ON`, needs Poco (Net, NetSSL, Crypto) |
| S3 assimilator (`s3://` sources in OMNI files) | **Not included** | `-DCAE_ENABLE_S3=ON`, needs Poco **and** the AWS SDK for C++ (`aws-sdk-cpp`, component `s3`) |

Without the assimilator, an OMNI transfer with an `s3://` source fails with
`S3 protocol requested but S3 support not compiled in`.

You also need:

- An AWS account, or temporary keys from your organization's AWS SSO portal.
- Outbound HTTPS from every node that runs the runtime to
  `s3.<region>.amazonaws.com`. On HPC clusters, check this from a compute
  node, not just the login node:
  ```bash
  curl -s -o /dev/null -w "HTTP %{http_code}\n" https://s3.us-east-2.amazonaws.com/
  ```
  Any HTTP status (for example `307`) means the endpoint is reachable.

## 1. Install the pip package

Use a dedicated virtual environment:

```bash
python3 -m venv ~/venv-iowarp
~/venv-iowarp/bin/pip install --upgrade pip
~/venv-iowarp/bin/pip install iowarp-core
source ~/venv-iowarp/bin/activate      # puts clio_run and clio_cte_bench on PATH
```

## 2. Install the AWS CLI

The AWS CLI v2 installs without root. These commands put it in `~/aws-cli`,
with the `aws` command in `~/bin`:

```bash
mkdir -p ~/awscli-dl && cd ~/awscli-dl
curl -sSLo awscliv2.zip https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip
unzip -q awscliv2.zip
./aws/install -i ~/aws-cli -b ~/bin
cd ~ && rm -rf ~/awscli-dl
aws --version          # add ~/bin to PATH if this is not found
```

For ARM64 nodes, download `awscli-exe-linux-aarch64.zip` instead.

## 3. Sign in to AWS

Pick the option that matches how you sign in to the AWS console.

**Personal account or IAM user, browser sign-in (recommended):**

```bash
aws login
```

This prints a link to open in a browser, so it also works over SSH. It
requires AWS CLI 2.32 or newer.

**Organization SSO portal (`*.awsapps.com/start`):**

```bash
aws configure sso
```

**An access key you created in the console:**

```bash
aws configure          # prompts for key ID, secret, region, output format
```

To create the key, sign in to the console and open the account menu (top
right) → **Security credentials** → **Access keys** → **Create access key** →
**Command Line Interface (CLI)**. The secret is shown only once. Do not create
access keys for the root user (an email address sign-in); create an IAM user
first. See [Least-privilege credentials](#least-privilege-credentials).

Confirm that you are signed in and see which region is set:

```bash
aws sts get-caller-identity
aws configure get region
```

## 4. Create a bucket

Bucket names are global across all of AWS, so add a random suffix:

```bash
BUCKET="clio-s3-test-$(head -c4 /dev/urandom | od -An -tx1 | tr -d ' \n')"
REGION=us-east-2
aws s3 mb "s3://$BUCKET" --region "$REGION"
aws s3api head-bucket --bucket "$BUCKET" --region "$REGION"
echo "$BUCKET"
```

The runtime does not create buckets unless you set `allow_bucket_create: true`
(or `S3_ALLOW_BUCKET_CREATE=1`). Without it, a missing bucket is reported as an
error naming the bucket, so a typo cannot silently create a new one.

## 5. Give the runtime its credentials

The S3 block device reads its credentials from the environment of the process
that starts the runtime, or from the `s3:` block of its config.

`aws login` and `aws configure sso` keep their credentials in a cache, not in
`~/.aws/credentials`. Export them into the shell that will start the runtime:

```bash
eval "$(aws configure export-credentials --format env)"
export AWS_DEFAULT_REGION=$REGION
```

This sets `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `AWS_SESSION_TOKEN`.
These keys are temporary, typically valid for a few hours. When they expire,
run `aws login` and the export again, then restart the runtime.

Prefer environment variables to putting keys in the config file: the runtime
copies the config's keys into its pool log under `conf_dir`.

## 6. Write the runtime config

Save this as `clio_s3.yaml`. It defines one CTE storage tier in the bucket:

```yaml
networking:
  port: 9413

compose:
  # DRAM block device (required for the shared memory allocator)
  - mod_name: clio_bdev
    pool_name: "ram::chi_default_bdev"
    pool_query: local
    pool_id: "301.0"
    bdev_type: ram
    capacity: "2g"

  # CTE with a single S3-backed tier
  - mod_name: clio_cte_core
    pool_name: cte_main
    pool_query: local
    pool_id: "512.0"
    storage:
      - path: "s3://${S3_TEST_BUCKET}/clio-s3-test"
        bdev_type: "s3"
        capacity_limit: "10GB"
        score: 0.5
        persistence_level: "long_term"
        # Region, endpoint and keys come from AWS_DEFAULT_REGION,
        # S3_ENDPOINT and AWS_* in the environment.
```

The path is `s3://<bucket>/<prefix>`. CTE appends `_node<N>` to each node's
tier, so node 0's objects are under `clio-s3-test_node0/`.

:::caution
`${VAR}` is expanded in `path`, but **not** inside an `s3:` block. A value
such as `region: "${AWS_DEFAULT_REGION}"` reaches the runtime as a literal
string. Inside `s3:`, write literal values, or leave the key out and set the
environment variable instead.
:::

## 7. Run a put/get test

Start the runtime with a clean state, wait until it is up, and write and read
16 blobs of 1 MiB each through CTE:

```bash
export S3_TEST_BUCKET=$BUCKET
export CLIO_SERVER_CONF=$PWD/clio_s3.yaml

clio_run --local start --fresh > runtime.log 2>&1 &
until clio_run --local status 2>/dev/null | grep -q running; do sleep 1; done
grep -i "s3 bdev" runtime.log

clio_cte_bench --op PutGet --threads 1 --depth 1 --io-size 1m --io-count 16
```

A working tier logs this line at startup:

```
INFO Init S3 bdev ready: bucket='clio-s3-test-d806c972' prefix='clio-s3-test_node0' region='us-east-2' endpoint='' capacity=...
```

The benchmark should finish with no `PutBlob`/`GetBlob` errors and report
`Total ops: 16`. Then check that the objects are in the bucket:

```bash
aws s3 ls "s3://$BUCKET/clio-s3-test_node0/"
aws s3 ls "s3://$BUCKET" --recursive --summarize | tail -2
```

You should see 16 `block_<offset>` objects totaling 16,777,216 bytes.

`clio_cte_bench` checks return codes; it does not compare the bytes it reads
back. Each thread fills its buffer with its thread index, so with one thread
every object is all zeros. To inspect one:

```bash
aws s3 cp "s3://$BUCKET/clio-s3-test_node0/block_0" - | od -An -tx1 | sort -u
```

Expect about 2 MB/s with one thread and depth 1: every 1 MiB put and get is a
separate HTTPS round trip. Use more threads (`--threads`) and a deeper queue
(`--depth`) to measure throughput.

## 8. Stop and clean up

```bash
clio_run --local stop
aws s3 rb "s3://$BUCKET" --force     # deletes every object, then the bucket
```

## S3 settings reference

Settings go in an `s3:` block on the pool or tier entry. Every key falls back
to the environment variable listed next to it.

| Key | Environment variable | Default | Description |
|-----|----------------------|---------|-------------|
| `access_key_id` | `AWS_ACCESS_KEY_ID` | — (required) | Access key ID. |
| `secret_access_key` | `AWS_SECRET_ACCESS_KEY` | — (required) | Secret access key. |
| `session_token` | `AWS_SESSION_TOKEN` | — | Needed for temporary keys (`aws login`, SSO, keys starting with `ASIA`). |
| `region` | `AWS_DEFAULT_REGION` | `us-east-1` | Region of the bucket. |
| `endpoint` | `S3_ENDPOINT` | AWS | Endpoint of an S3-compatible store, e.g. `http://127.0.0.1:9000`. Setting it switches to path-style addressing (MinIO, R2). |
| `allow_bucket_create` | `S3_ALLOW_BUCKET_CREATE=1` | `false` | Create the bucket if it does not exist. |

## Least-privilege credentials

Your own sign-in works for a quick test. For long-lived deployments, create
an IAM user that can only use one bucket. In the console, go to **IAM →
Users → Create user** (no console access), and attach this policy, with your
bucket name filled in:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    { "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::YOUR-BUCKET" },
    { "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::YOUR-BUCKET/*" }
  ]
}
```

Then open the user → **Security credentials** → **Create access key** →
**Application running outside AWS**, and use `aws configure` (or the
environment variables) with that key. These keys do not expire, so delete
them when you no longer need them.

## Troubleshooting

| Symptom | Cause and fix |
|---------|---------------|
| `S3 bucket head exception: Host not found: <bucket>.s3.${aws_default_region}.amazonaws.com` | A `${VAR}` inside the `s3:` block was not expanded. Use a literal value, or remove the key and set the environment variable. |
| `S3 bdev: no credentials. Give access_key_id and secret_access_key ...` | The process that started the runtime has no keys. Run the `export-credentials` step in the same shell, then restart the runtime. |
| `RegisterTarget Failed to create bdev container s3://...`, then `PutBlob rc=11` | The S3 tier failed to start and CTE has no target to write to. The real error is a few lines earlier in the runtime log. |
| `ExpiredToken` or `403` after a few hours | Temporary keys expired. Run `aws login`, export again, and restart the runtime. |
| `404` / bucket not found | The bucket name or region is wrong, or the bucket does not exist. Check with `aws s3api head-bucket --bucket <name>`. |
| Request timeouts on compute nodes only | The nodes have no outbound internet access. Check with the `curl` command under [What you need](#what-you-need). |
